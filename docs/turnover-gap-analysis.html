IBM i Turnover tool vs. the turnover process

Gap analysisLive mode not yet run on a real IBM iDeploys for real in Live mode

Short answer: it promotes for real, but only in Live mode, and only after approval.

In Live mode the Deploy button runs the approved script step by step against the target IBM i over ODBC: SQL changes (CREATE, ALTER, LABEL), CL through QSYS2.QCMDEXC (backups with CRTDUPOBJ, source copy, compiles, GRTOBJAUT, CHGUSRPRF, CRTDTAQ …), then post-checks. It stops at the first failure, and Rollback undoes the steps that ran.

In Sample mode (what is configured today) it only shows: deploy and dry run are simulated and nothing is sent anywhere.

What has to be true before Live deploys can be trusted

ConditionWhy
Run on one non-production partition firstThe live code has been checked against a fake driver and by review, never against a real IBM i.
The ODBC profile has the authority the steps needCreating objects, CRTDUPOBJ, compiles, GRTOBJAUT; CHGUSRPRF/CRTUSRPRF need *SECADM. Missing authority fails the step (and stops the deploy).
Data is not promotedBy design it moves structure and code only. Table rows, data-area values (except when ticked) and queue entries stay where they are.
Compile options are replayedActivation group, target release, USRPRF, optimization, SQL options and bound service programs come from the catalog. Multi-module objects remain manual builds.

Whole-environment driftCompares everything, not just what is in a request, so changes made outside the process (in QA or Prod) show up.
Data-safety pre-checksOrphan rows before a foreign key, duplicates before a unique index, values that would be truncated, NULLs before NOT NULL, check-pending constraints. All run before anything changes.

One-page glossary: where the tool is stronger than the manual turnover process

Drift detection
Finds every structural difference between environments, including ones nobody filed a request for.
Rule codes
Each risk has a stable code (FK003, SEQ003, PGM004…) with a plain explanation and fix, so reviews are consistent.
Blocker
A finding that would fail or corrupt the deployment; it cannot ship to Prod until resolved.
Pre-check
A query that must return 0 before anything changes, e.g. no orphan rows, no duplicate keys.
Level check (CPF4131)
A program compiled against an old file format. The tool finds and recompiles every one automatically.
Library map
Logical names (ORDERS) mapped to physical libraries per environment, so code is rewritten correctly on promotion.
Profile map
The same for service accounts (SVCORDDEV → SVCORDQA), used in authorities and job descriptions.
Emergency-fix guard
Blocks overwriting a fix made directly in a higher environment until it is retrofitted.
Dependency closure
A selected change cannot ship without what it needs (parent table, new column, unique key).
Frozen script
Approvers sign a hashed script; deploy runs exactly that, against an unchanged target.
Backup library
Each package backs up the objects it changes (with data for tables) before changing them.
Rollback
Every step records how to undo itself; rollback runs the completed steps in reverse.
Dry run
Walks the whole plan without touching IBM i.
Snapshot
A point-in-time copy of an environment's structure; compare any two points or a point with live.
Masking
Secret-looking values are hidden on screen, in CSV and in scripts; passwords are never read.
Fail closed
Bad configuration, a failed catalog read or a missing role stops the action instead of guessing.
Separation of duties
Requester cannot approve; Prod needs two approvers; deploy needs the release-manager role.
Report view
One row per changed attribute with before and after values, exportable to Excel.

Bottom line: the tool is stronger at finding and explaining risk and governing the change. A mature turnover product still has the edge in years of production use and in object types this tool does not cover (SQL packages, subsystems, exit programs). Version 1.1 closed the three high-risk gaps and 1.2 the medium ones; what remains is low risk (compile listings, resuming a failed deploy, a pipeline API) plus a first run on a real non-production IBM i.
